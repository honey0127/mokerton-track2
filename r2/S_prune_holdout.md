# 2차 라운드 트랙 S (구조적 채널 프루닝) holdout 결과 (2026-10-23, 공용 PC)

규칙: `DECISION_R2.md` 트랙 S. 프루닝 모델의 INT8 holdout mAP 가 같은 해상도 B·D INT8 보다 **0.5점 이내**로 낮고,
M1 INT8 p50 이 **10% 이상** 빠르면 대체한다.

**결론: 4개 모두 정확도 조건에서 탈락. 트랙 S 채택 없음.** 정확도에서 이미 탈락했으므로 M1 속도 측정은 하지 않는다.

## 조건

- 재학습: 공용 PC RTX 5070, `scripts/prune_p34.py train` (epochs 100, batch 8, seed 0). 10/15 21:42 ~ 10/17 01:56.
  B_m75 는 1회차 DataLoader 시스템 RAM `MemoryError`, 2회차 epoch 11 에서 중단, 3회차에 같은 설정(batch 8)으로 완주.
- 비교 기준 B·D 도 **같은 PC·같은 환경에서 다시 export·양자화**했다 (`DECISION_R2.md` 보충: 같은 PC·같은 보정 이미지 256장).
  기준 가중치는 `MODELS.sha256` 과 해시가 같은 `runs/kitti_1280_p34`, `runs/kitti_640_p34` 의 `best.pt`.
- 환경: i9-14900KF, ultralytics 8.4.135, onnx 1.22.0, onnxruntime 1.29.0.
- INT8: `int8-mixed-percentile` (`head_nodes.py` 제외 45노드, Percentile, 보정 train 256장 seed 0).
- 채점: holdout 500장, Moderate AP40, `kitti_eval.py` (official-port), 2스레드.
- 실행 스크립트 `r2/run_pc5070.sh`, 원본 기록 `r2/pc5070/results.jsonl`, 상세 `r2/pc5070/ap40/`, 가중치 해시 `r2/pc5070/weights.sha256`.

## 관찰

- 같은 PC 에서 다시 만든 기준 B·D 의 FP32 holdout 은 1차 기록(97.17 / 91.67)과 같다. INT8 은 2차 리눅스 환경
  재양자화본(`repro_*`: 96.60 / 89.90)보다 B +0.10, D +0.25 높게 나왔다. 환경을 맞추지 않으면 판정이 흔들릴 수 있는 크기다.
- 프루닝은 FP32 손실보다 INT8 손실을 더 키웠다. FP32→INT8 손실: B 0.47 → B_m75 0.83 → B_m60 1.72. Pedestrian 이 가장 크게 떨어진다.
- B_m75 는 0.16점 차이로 탈락했다. 규칙은 결과를 보기 전에 커밋했으므로 기준을 바꾸지 않는다.
- 트랙 P 에서 D 의 INT8 방식이 바뀌더라도(예: P1 박스 경로 FP32), D 프루닝 모델은 FP32 에서 이미 기준 대비 −1.91 / −3.33 이라
  결론이 바뀔 가능성은 낮다.
